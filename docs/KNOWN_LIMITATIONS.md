# Quorum — Known Limitations

Honest disclosure of current limitations. Each item notes the impact and the
planned path to resolve it.

## 1. Per-member proof mode is the default in the CLI

The SDK and CLI currently generate **one proof per approval** (fast, ~6 min
real proving per approval). The aggregated single-proof mode (M approvals in
one receipt) is implemented in the circuit design but the CLI records claims
per-member.

- **Impact:** M on-chain claim transactions (one per approval) rather than one;
  only nullifiers are recorded either way — no identity leakage.
- **Path:** add an `--aggregate` CLI flag that batches approvals into one
  receipt before the on-chain `approve` call (same guest, same image ID).

## 2. Testnet deployment requires a funded LEZ wallet

`F6/F7/S1/W2` (live testnet multisig instance) are ready to execute but the
**deployment transaction needs a funded testnet wallet + signer**, which is
operator-side (seed phrase / keyring not committed to the repo). The full flow
is verified locally against the SPEL program and the demo script.

- **Impact:** on-chain evidence artifacts (program ID, deployment tx, per-step
  tx hashes) are generated by the operator via `scripts/regenerate-evidence.sh`.
- **Path:** provide the deploy key when testnet is accessible; re-run
  `regenerate-evidence.sh` and re-pin hashes.

## 3. LEZ testnet RPC exposes no per-transaction CU / gas-used

Same limitation the LP-0005 solution reported. `docs/BENCHMARKS.md` documents
Risc0 guest cycles and real proof timings instead of network CU.

- **Impact:** P1 (CU cost per operation) is partially met; proof cycles map
  directly to LEZ verification cost.
- **Path:** extend `docs/evidence/LEZ_TESTNET_COSTS.md` when the RPC exposes
  CU metadata.

## 4. Proof time is dominated by SHA-256 Merkle paths

~368 s per approval in real proving (RISC0_DEV_MODE=0, 16-core). Fine for a
treasury (proposals are rare), not for high-frequency voting.

- **Impact:** F5 (client-side on a laptop) is met, but interactive UX for
  rapid-fire approvals is slow.
- **Path:** precompute Merkle path hashing in the host; explore wider Merkle
  arity; aggregate M approvals per proof to amortize fixed overhead.

## 5. No independent security audit

The circuit is small by design (minimize audit surface) but has not been
audited.

## 6. Basecamp GUI is a starter app

`apps/basecamp-quorum` ships the core views (create / propose / approve /
execute / rotate) targeting the Logos Basecamp QML runtime. It is a thin
wrapper over the CLI/SDK — see its README for build/load instructions.

## 7. Hosted CI may be blocked by the GitHub account billing lock

The same strict CI (`fmt` + clippy `-D warnings` + tests) passes locally;
hosted jobs depend on the account-level billing state (same issue the LP-0005
submission hit).
